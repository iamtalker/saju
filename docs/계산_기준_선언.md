# 계산 기준 선언

버전 0.1 (2026-11-16 작성). 이 문서는 프로그램이 따르는 규칙을 한 곳에 모은 기준이다. 규칙을 바꾸면 이 문서의 버전을 올리고 변경 이유를 적는다. 기대값을 고쳐서 테스트를 맞추지 않는다.

## 1. 기준을 고르는 원칙

사주는 예측이 사실로 확인된 체계가 아니라 전통 규칙에 따른 해석 체계다. 타로처럼 정해진 관례를 따르는 것이므로, 이 문서의 기준은 **어떤 관례를 따르는지**를 정하고 밝히는 역할만 한다. 기준을 따른다고 결과가 사실이라는 뜻은 아니다. 화면과 내보내기에는 이 점을 계속 표시한다.

1. **정통 우선:** 고전 명리서(『자평진전』, 『적천수』, 『궁통보감』 등)에 나온 규칙이 있으면 그것을 먼저 쓴다.
2. **다수파 확인:** 현재 사용하는 규칙이 실제로 다수인지는 아직 확인하지 못했다. 다수파는 독립된 자료 여러 개가 같은 규칙을 쓸 때만 주장할 수 있다. 조사 문서([사주 심화 조사](사주_심화조사_자료와_구현판정.md))는 이 표본이 아직 없다고 밝힌다.
3. **잠정값 표시:** 원문과 다수파 모두 확인하지 못한 항목은 '잠정'으로 적고, 대안을 함께 기록한다.
4. **해석 출력 금지:** 신강·신약, 격국, 용신, 길흉은 원문 규칙과 예제가 확보되기 전까지 출력하지 않는다.

이 문서가 쓰는 '정통'과 '다수파'는 현재 확인한 자료 범위 안에서만 쓴 말이다. 원문을 직접 대조한 것이 아니다.

## 3. 해석 규칙

| 항목 | 현재 상태 |
|---|---|
| 신강·신약 | 출력하지 않음 |
| 격국 | 출력하지 않음 |
| 용신 | 출력하지 않음 |
| 조후 | 출력하지 않음 |
| 길흉·사건 예측 | 출력하지 않음 |

**v0.2 변경 (2026-11-16):** 일간별 "재미로 보는 문장" 카드를 추가했다. 이 문장은 근거가 없으며 전통 해석이나 예측이 아니라고 화면에 명시한다. 전통 해석 카드와 섞지 않는다. 또 "재물과 연애의 상징" 카드를 추가했다. 재성, 일지(배우자 자리), 도화살을 관례에 따른 상징으로만 설명하며 "관례 설명 · 예측이 아님"으로 표시한다. 사건·미래 예측과 인생 판정은 여전히 출력하지 않는다.

**추가 (2026-11-16, 후속):** 출생지 경도(선택)를 입력하면 진태양시와 균시차를 참고값으로 보여 준다. 균시차는 근사식(오차 약 0.5분)이며 기둥 계산에는 쓰지 않는다. 재미 풀이에 신강·신약(비겁·인성과 식상·재성·관성의 개수만 센 구분), 격국(월지 본기 이름 붙이기), 용신(재미 문장)을 추가했다. 이 세 항목은 실제 판정이 아니며 "재미" 표시를 붙인다. Markdown 내보내기에 계산 항목을 추가했다.

**재미 풀이 모음 추가 (2026-11-16):** 결과 맨 위에 "사주는 근거 없는 점술입니다. 아래 내용은 모두 재미로만 봐 주세요." 문구를 두고, 그 아래 성격 분석, 재물운, 연애운, 직업 성향, 재미 연봉 지수, 올해 좋은 달, 귀인(관례) 항목을 `fun-reading.js`의 고정 문장으로 보여 준다. 이 문장은 사용자가 요청한 재미용이며 전통 해석이나 예측이 아니다. LLM 해석은 아직 넣지 않았다.

**계산 항목 추가 (2026-11-16):** 띠(년지), 공망(일주 순 기준), 십신 개수(천간 3개와 지지 본기 4개), 올해 월별 간지(각 월 15일 기준), 오늘의 일진을 "계산 항목 · 해석 없음" 카드로 추가했다. 월별 간지는 15일 기준이라 절입 경계 근처 날짜가 달라질 수 있다.

해석 규칙을 넣으려면 다음이 먼저 있어야 한다.
- 채택한 고전의 원문 또는 교재 본문
- 그 규칙을 재현할 수 있는 예제 여러 개
- 규칙의 예외와 충돌 시 처리 방식

## 4. 다음에 확인할 것

1. 자시 기본값(밤 11시 또는 자정)이 정통 고전에서 어떻게 다루는지 원문을 확인한다.
2. 출생시간 보정 기본값 30분의 근거를 확인한다. 근거가 없으면 기본값을 바꿀지 검토한다.
3. 대운 순역행 규칙이 고전 원문과 일치하는지 확인한다.
4. 십이운성의 화토동궁·수토동궁 중 정통 쪽 원문을 확인한다.
5. 다수파 여부는 독립된 만세력 서비스와 교재 몇 곳을 같은 질문으로 비교해서만 판단한다.

## 5. 공개 구현 비교 (2026-11-16)

GitHub에서 받은 공개 구현 여섯 곳을 로컬에서 읽기만 했다. 실행하거나 코드를 복사하지 않았다. 대상은 `yhj1024/manseryeok`, `urstory/manseryeok-js`(`@fullstackfamily/manseryeok`), `hyunyoonsu/saju`, `jun0-ds/manseryeok`, `nanamix/korean-fortune-system`, `JwMudfish/saju`다. `alvamind/bazi-calculator-by-alvamind`는 README와 상수 파일만 훑었고 계산 규칙을 확인하지 못해 비교에서 뺐다.

**독립성 주의:** `nanamix`는 `lunar-java`에, `JwMudfish`는 `korean-lunar-calendar`에 계산을 위임한다. 절입 값은 같은 천문 계산에서 나올 수 있으므로 다수파 판단은 **규칙 선택**에 한정한다. 계산 결과 값이 같다는 것은 독립 검증이 아니다.

| 항목 | 다수 선택 | 예외 |
|---|---|---|
| 대운 방향 | 양남음녀 순행 (yhj1024, hyunyoonsu, jun0-ds, JwMudfish 코드 확인, nanamix 명세 확인) | 없음 |
| 대운수 | 일수 ÷ 3, 반올림, 최소 1년 (3곳) | yhj1024는 개월 잔여 보존 |
| 자시 전환 | 23시 전환 (3곳) | hyunyoonsu 자정 기본 |
| 지장간 배열 | 지지별 천간 집합 동일 (3곳) | 가중치는 jun0-ds만 사용, 戌·未 표시 순서 차이 |
| 십이운성 | 화토동궁, 음간 역행 (2곳) | JwMudfish는 수토동궁 |
| 시지 | 23~01시 자시 (4곳) | 없음 |

이 비교로 바뀐 것: 대운수를 개월 단위 반올림에서 년 단위 반올림으로 바꾸었다. 검증 기준은 nanamix의 기준 사례(1981-03-20 01:59, 남성, 보정 −30분 → 대운수 5, 첫 대운 경인)와 일치한다.
